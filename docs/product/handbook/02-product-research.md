# 02 成熟产品调研 · 03 功能矩阵

调研重点是**功能组织、模块边界、交互与公开技术事实**。未公开的内部实现一律标为推测。

## 02 成熟产品调研

选取 8 个代表产品。本仓库定位更接近 **Pixlr E / Photopea 的轻量图层编辑**，不是 Figma 协同，也不是 Canva 模板商城。

### 2.1 产品画像

| 产品 | 定位 | 公开可确认 | 对本仓库的借鉴 |
|---|---|---|---|
| Photoshop | 专业栅格 | 图层/调整图层/智能对象/历史画笔；桌面为主 | 图层真源、非破坏裁剪与滤镜、历史按「完成手势」一条 |
| Photopea | 浏览器 PS | [官方博客](https://blog.photopea.com/photopea-1-3.html)：图层像素进 WebGL；混合/样式/缩放用 GPU；全客户端、文件不上传；2024 起 WebGL 2.0 | GPU 合成、客户端本地文件、PSD 级能力**不**作为本仓库目标 |
| Figma | 矢量设计 + 协同 | 官方/Config：C++ 引擎编成 WASM；UI 为 TS/React；渲染 WebGL，2025 起 WebGPU+WebGL fallback；文档模型在 WASM 堆 | **壳与引擎分离**；本仓库用 Pinia+Pixi 达到同类边界，不上 C++/WASM |
| Canva | 在线设计 | 模板、页面、素材、文本为主；公开资料偏产品而非渲染内核 | 属性面板随选中对象切换；素材系统【后续演进】 |
| 美图秀秀 | 大众修图 | 滤镜、美颜、贴纸、左侧工作区 Tab + 二级面板 | **左侧 Tab 信息架构**（feat-031）；滤镜/贴纸/抠图按 Tab 挂载；文档仍是图层对象，不要做成「无图层一步流水线」 |
| Pixlr | 在线修图 | E（编辑器）/X（快速）双产品；E 有图层 | 工具分层：快速修 vs 对象编辑；本仓库走 E 路线 |
| Adobe Express | 轻量设计 | 模板、文字、品牌套件 | 文本+素材优先；本仓库先图后字 |
| 稿定设计 | 国内设计编辑器 | 模板、素材、排版（产品行为） | 中文排版与素材库【后续演进】 |

> 公开资料无法确认 Canva / 美图 / 稿定 / Express 的 Canvas 实现（DOM / Canvas2D / WebGL / 自研）。以下涉及其内部渲染的内容均为**基于产品行为的推测**，不作为本仓库技术依据。

### 2.2 功能组织（行为层，可观察）

成熟编辑器几乎都把能力分成四类：

| 类别 | 出现位置 | 例子 |
|---|---|---|
| 文档级 | 顶栏 / 文件菜单 | 打开、保存、导出、撤销、适配 |
| 工作区级 | 左侧图标 Tab + 邻接面板 | 调整 / 滤镜调色 / 人像 / 抠图 / 画笔 / 素材 |
| 工具级 | 当前工作区面板内；可与平移互斥 | 裁剪、旋转、尺寸、滤镜滑条、抠图、画几何 |
| 对象级 | 选中后右侧属性 + 画布手柄 | 变换、透明度、描边 |
| 结构级 | 图层面板 | 显隐、锁定、排序、命名 |

【保持现有架构】本仓库壳是「顶栏 / 左侧工作区（Tab+面板） / 中央 host / 右侧面板」。**布局与视觉参考美图**（浅底、顶栏三分区、粉/红强调、左图标 Tab），不学无图层全屏一步流程，不抄会员/云账号。文档真源仍是 `layers[]`。

**工具模式 vs 编辑模式**

- Figma / PS / Photopea：当前工具决定左键含义（选择拖对象，平移拖视口，裁剪进裁剪会话）。
- 【保持现有架构】feat-007 已规定：左键拖视口只在平移工具 / 空格 / 中键；把左键留给 feat-008 选择。

**选中后能力**

对象选中 → 包围盒 + 手柄 + 右侧属性。全局能力（撤销、导出、适配）不进对象属性。

### 2.4 工程架构（仅公开事实 + 对本仓库含义）

#### Photopea（公开）

- 图层像素存在 WebGL 内存；混合、样式、视口缩放走 GPU。
- 全客户端，文件不离开设备。
- 对 2048×1152、10 层、3 个图层样式：无 WebGL ~850ms / 有 WebGL ~55ms（官方 1.3 博客）。

**含义：** 本仓库已用 PixiJS WebGL，方向一致。不要学 PS 那样把每层做成独立离屏位图再 CPU 合成，除非做到 Photopea 级自研合成器（【后续演进】且不建议）。

#### Figma（公开）

- UI（React/TS）与文档/渲染（C++ → WASM → WebGL/WebGPU）严格分离。
- 文档不活在 React state 里。
- 瓦片/脏区渲染（第三方研究与官方演讲口径一致）。

**含义：** 【保持现有架构】Vue 不持有 DisplayObject；文档在 Pinia 而不是组件局部 state。不必引入 WASM。

#### Photoshop（公开产品模型，非 Web 内核）

- 图层栈 + 调整图层 + 智能对象 = 非破坏编辑。
- History 是步骤列表，画笔类工具按 stroke 提交。

**含义：** 裁剪与滤镜写入图层字段（Crop Model / ColorAdjust），不立刻打进原纹理。【建议新增】feat-010/011。

#### 其余产品

内部渲染栈**公开资料无法确认**。行为上：Canva/Express/稿定偏「页面+元素」；美图偏「当前图+效果栈」。本仓库采用 **Document.layers[] 对象模型**（PS/Photopea/Pixlr E），不采用单图效果管道。

### 3.1 底层基础 vs 业务编辑

| 底层（Engine / 文档内核） | 业务编辑（可插件化） |
|---|---|
| Scene 分层、坐标、视口 | 调整面板（裁剪/旋转/尺寸）、滤镜预设 |
| Object/Layer 模型、选中 | 素材几何、贴纸、抠图会话 |
| Transform 数学、指针会话 | 人像/画笔（调研后） |
| Command / History | 导出格式扩展 |
| 资源加载与销毁 | AI、多页 |

【保持现有架构】底层落在 `model/` + `store/` + `scene/` + `core/`；业务工具落在 `tools/` + `components/`。新业务禁止在 `core/usePixiApp` 里长逻辑。
